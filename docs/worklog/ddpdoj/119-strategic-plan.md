The "$28Cxxx cue family" label is invented: no doc, source file, or worklog uses it. `$28C02A` is real BGM/streaming code, reached via PC-relative JSR, not a named cue table. The correction strengthens the recommendation: the owner's binding decision is older and more explicit than the brief implied. (Recon 2)

2. **"$81308C-style gates" (slowdown brief) - WRONG ADDRESS.** `$81308C` is the global game-state word (attract / 2-player / collision-mode selector), not a slowdown gate. It scales WORK indirectly through load but does not itself gate slowdown. The actual (A)-mechanism gate is the **`$803940` vblank semaphore** (`isr.js`, `framesync.js`). Replace "$81308C-style gates" with "$803940 semaphore gates" in all future briefs. (Recon 3)

3. **"Boss explosion art is missing" (defects brief, item a) - FALSE.** 166/166 sprite streams present, 0 missing. W107 fixed the real gap (emitters were `note()` placeholders, not `spawnEffect` calls). The explosion is statically closed. This REPRIORITIZES the defect: (a) is verification, not work. (Recon 5)

4. **"4,017 records without art" (defects brief, item e) - STALE by two waves.** W98 reduced it to 64 (30 null + 34 in one bullet-animation range at lf2247-2261). W107/W111/W118 shipped more art since. Live figure is at most 64, likely lower. Negligible. (Recon 5)

5. **"819 instructions" for $28D9AA (stage-end brief) - MISCOUNTED.** Linear span is 314 instructions; the whole result-screen region is 835. The figure appears in `stageend.js:49`, `hud.js:145`, and HANDOVER but matches no measured boundary. The work sizing (~1,000-1,400 instructions across 5-6 routines) is unaffected. (Recon 1)

6. **"7 unported type-5 calls" (defects brief, item g) - NOW 6.** W111 ported the bee (#4). Of the remaining 6, one (#6 `$2890F2`) is a DECLARED REFUSAL, not a gap. (Recon 5)

**No inter-recon contradictions found.** The five reports are complementary.

**Two cross-recon convergences (same item, two recons, same conclusion):**

## 1. RECOMMENDED ORDER OF PHASES

### PHASE 0 - CORRECTNESS GUARD (first; cheap, parallel recons)

Two cheap, independent recons that protect the "stage 1 is correct" foundation. Everything built on a wrong stage 1 is wasted, so these precede all completion and expansion work.

**0a. RANK type-10 recon** (Recon 5g)
- The ONLY open item that can silently falsify "stage 1 feature-complete." Object type 10 = RANK (`$260794`, priority `$1F`, runs FIRST every frame) is unported. W105 could not resolve whether `score.js`'s inline rank arithmetic substitutes for the rank object's per-frame `$2608D2`. If it does not, stage-1 scoring is diverging every frame. Invisible to a player; load-bearing for owner decision 3 ("one wrong rank gain breaks the route").
- First wave: 1 recon. Closure-walk `$260794`, compare its per-frame work against `score.js`'s inline rank arithmetic.
- Biggest risk: if it diverges, the fix could touch the frame-exact chain meter decrement (`score.js:779-783`, priority `$0009`), which owner decision 3 requires to be frame-exact.

**0b. (C) sub-handler disassembly** (Recon 3 L1 / Recon 4 Wave 4)
- Open since W2. W2 measured the TOP-LEVEL driver (`$2410BC`, `moveq #$13,D0 / dbra`, 20 slots, no budget test) and found `object_slots_processed == object_slots_live` on all 696 forced-overrun frames. But the 20 per-type handlers' own sub-table loops (RAM ranges `$813660`, `$8145A0`, `$810570`, `$81C8FC`, `$80B058`) were never examined for budget tests. If any truncates under load, the port is "a different game that runs slowly": wrong objects update in wrong order, which is gameplay not pace, and cannot be retrofitted without rewriting the object driver. `budget.js` is already shaped to absorb the answer as one constant.
- First wave: 1 recon. Write-tap + CURPC, one sub-table at a time, across the five RAM ranges.
- Biggest risk: if a truncation is found, the object driver needs per-type budget tests in original-table order. Structural rewrite, not a constant.

**Reasoning for Phase 0 first:** Both items are one recon each, independent, and protect correctness. The corpus is a passive fly-around run that never triggers slowdown, so (C) has never been exercised and RANK runs every frame regardless. Neither was closed in 98 waves. The cost of being wrong on either is silent divergence that compounds through every future wave.

Cheap data export that proves the stage-end machine chains stages correctly. Independent of Phase 2.

But if the spawn-table stride is wrong (derived as stride-16 from `add.w D0,D0; add.w D0,D0` at `$263392`, never cross-checked against a known stage-2 spawn because no run has ever reached stage 2), the pointer could land INSIDE the movement-script window, and the spawn walker would interpret movement-script bytes as 8-byte spawn records. Silent garbage enemies, not a clean throw. This MUST be verified before claiming "bootable."

**4c. Live-page REC + PLAY** (Recon 4 Waves 2-3)

- Sizing: small-medium each. Depends on 4a.

## 4. WHAT NOT TO DO YET (and why)

1. **Stage-2 content (enemies, midboss, boss, bullets).** The largest item by far, comparable to all of stage 1's content effort. Should be recon-first (enemy census, boss recon) before any impl. Only proceed if the owner explicitly wants to go past stage 1, and only after Phases 2+3 prove the architecture chains correctly.

2. **ICS2115 audible synthesis (Sound Wave E).** A research problem modeled from the ICS2115 datasheet, deliberately not MAME (whose own model is "incompletely verified"). Schedule only if the owner wants audible output and accepts the datasheet reference. State-exact work (Waves A-D) is tractable and is the project's proven discipline; audible output must not be allowed to look like "the last 10% of the port."

3. **Calibrating slowdown against MAME alone.** Explicitly forbidden (NOTES-slowdown-oracle.md). Would launder MAME's known-inaccurate PGM timing into "truth." MiSTer is the proposed second witness; even MiSTer-calibrated figures must be labelled as such, not "hardware."

4. **A shared synthesizer across the three games.** Not real. Batman = Game Boy DMG (4 ch), Gradius = NES APU (5 ch), DOJ = ICS2115 (32-voice wavetable). Three different chips. The shared asset is the METHOD (state-exact command/register stream, no audio-buffer gate), not a synth. A shared Web Audio output shim (master gain, mute, pause, unlock-on-gesture) is the one piece of shareable runtime code and is worth ~1 wave, but only once DOJ has something to pipe through it.

5. **Skipping the owner's W27 process for sound.** W27 is explicit: 10 recons + fable architect, THEN waves. The subsystem is genuinely unlike anything ported so far. The codebase recons now have a concrete head start (captures in `rip/sound/`, the disassembly above). Do not shortcut to Wave A without the recons.

6. **Title/attract text bodies (defect item f).** DOJ boots straight into the stage with NO title/attract screen. The text pipeline (`$240DC2` printer, `$141258` IRQ6 flush) is shipped. Only spawn-time text (`$253xxx`) is in-play. Defer; low priority.

7. **Pursuing a real-board recording aggressively.** None exists in the project. The scroll-clock method depends on one. Until one surfaces organically, label all calibration as emulator-derived (MAME + MiSTer cross-check), not hardware-truth.
