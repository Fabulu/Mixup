# W335: type `$49`, and a prototype that deliberately overlaps its own handler

Status: suite **2386/2386**, green, no skips (2375 + 11). Sweep 0 missing. `dojcoverage.py` both OK
lines. 422 ROM windows, up 6.

Stage 5 goes from **TEN types with no handler over 29 records to NINE over 27**. `$49` is the
sweeping fan emplacement: `$27159E` init, `$2715A6` initBody, `$271640` handler.

## THE ENTRY POINTS, VERIFIED RATHER THAN INFERRED

    $267824 + $49 * 8 = $267A6C:   0027159e 00271640

`$2715A4` is an `rts` and `codexref` finds NO code reference to `$2715A6`. It runs because
`spawn.js:219` computes `initBody = init + 8` (`$26361A addq.w #8,A1`), so the init exists only to
declare the sub-record count (`($4,A5) = 0`, one record) and the machinery calls the body. `$81` is
the identical shape. Worth pinning in a test, because a caller-less routine with nothing branching to
it looks like a bad disassembly and is not one.

## THE FINDING: THE SUB PROTOTYPE RUNS FOUR BYTES INTO THE HANDLER

`loadSubProto` copies `$20` bytes from `$271624`, so `$271624..$271643`. **The handler starts at
`$271640`.** The record's `+$1C..+$1F` therefore receive `725C C216`, which is
`moveq #$5C,D1 / and.b (A6),D1`.

This is the cartridge overlapping data with code, not an off-by-one, and the init proves it knows:
`$2715D2` writes `+$1C` and `$2715DE` writes `+$1D` immediately, so only `+$1E`/`+$1F` keep code
bytes, as `$C2 $16`. **The window must be declared as `$271616 + $2E` and must NOT be trimmed back to
`$271640`**, because `loadSubProto` reads the whole `$20` and `RomWindows` only serves a read from a
window containing it WHOLE. The window comment says so at length; a later reader tidying it to end at
the handler would break the spawn.

## THREE MORE TRANSCRIPTION TRAPS

**1. `$2716D8 tst.w $271774.l` IS DEAD AND IS OMITTED.** `$271774` is inside this same routine and
the word there is `$41FA`, the `lea` opcode -- so it reads code as data. `$2716DE subq.b` then sets
every flag before `$2716E2 bcc` reads carry, so the `tst.w` cannot affect anything. **Third instance
in stage 5 of this ROM indexing its own instruction stream**, after W326's `$27460A` ramp and W332's
`$25DAC2`. At three it stops being a curiosity: when a stage-5 routine reads an address inside
itself, check whether the target is code before modelling the read.

**2. `$27172C neg.w D3` where `$27171E` loaded D3 with `move.l`.** A WORD negate on a long: the low
half flips, no borrow reaches the high half. The offsets at `$271814` are packed pairs (high word X,
low word Y, entry 0 = `$0080FD00`), so the mirrored variant flips Y and keeps X. Then `$27172E add.l`
adds both halves at once, which DOES let a low-word carry reach X. A long negate would slide the
mirrored formation sideways.

**3. `($20,A5)` HOLDS A POINTER TO A FORMATION FLAG.** `$2715F4..$271610` picks `$8130E0` when the
scroll clock is below `$260` and `$8130E4` otherwise, stores the ADDRESS, and writes 1 through it.
Both exits clear it through the pointer -- the death arm at `$27168A` and the off-screen free at
`$2716BE`. So the stage's two `$49` formations retire independent flags, and storing the value would
break both exits at once.

## THE DAMAGE ARM IS THE FIRST *SIMPLE* MEMBER OF THE `$5C` FAMILY

`$271640 moveq #$5C,D1 / and.b (A6),D1` is the mask the family is named for, and this is its fifth
member -- but there is no `hpFull` reload and no palette DECISION, just base `($18,A5)` and XOR mask
`($19,A5)`. Routing it through `damageArm5C` would have invented both, which is why the handoff said
to write it inline. The parameter table now records five members with this one marked simple.

The alive test is also its own idiom: `$2716A4 ext.l` then `addi.l #$4000` then `cmpi.l #$2000 / bgt`
-- a **signed long** compare, where `$1B` and `$81` do the same job with two `addi.w`s.

## THE SWEEP: ONE COUNTER, TWO INDEX CONVENTIONS, AND A FREEZE THAT DOES NOT STALL IT

`($1C,A5)` steps `addq.w #4` and wraps at `$78`, so **30 steps**. Four tables:

    $27179C   30 LONGS   index RAW      the draw's sprite records, $316494 ascending by $2A4
    $271814   30 LONGS   index RAW      the packed muzzle offsets
    $27188C   30 WORDS   index ASR 1    ($17,A5) SET   -- $66 ascending by 6, then back down
    $271904   30 WORDS   index ASR 1    ($17,A5) CLEAR -- $9A descending by 6, then back up

The word values run out and return, so the attack is a fan that sweeps and comes back over 30 frames.
`($17,A5)` picks the direction AND the mirror, and the init is its sole writer, on the one record
whose scroll trigger is exactly `$1F3`. **Read as a threshold instead of an equality that would arm
every later record.**

`$2716EC tst.w $8130D4 / bne $271760` branches PAST the fire and **INTO** the counter step, so a
freeze silences the fan without stalling its sweep. A port that returned early on freeze would
desynchronise the formation. One test computes the branch target arithmetically (`$2716F2 + 2 + $6C
== $271760`) rather than trusting the label.

## WHAT IS DELIBERATELY A NOTE AND NOT PORTED

`$49` fires THREE shots and only the first specifies its own registers. `$271736 jsr $2816F6` has
D0 = 4, D1 from the sweep table, D2 the biased position, D3 = D4 = 0. `$271742 jsr $281764` and
`$27175A jsr $281744` (the latter gated on scroll `>= $268`) **set only D0 and inherit D1..D4 from
whatever `$2816F6` left behind.**

That is the same shape as `draw81`'s third emit, which the port transcribes rather than tidies -- but
there the producing routine's register effects had been read first, and here they have not. Assuming
D1..D4 survive the call would be an invention with a visible consequence: two of this type's three
bullets. So the first shot is ported and the other two are a `note` at `$271742` that names the
measurement which unblocks them: **disassemble `$2816F6` to its `rts` and record which of D1..D4 it
preserves.**

The type is fully registered either way, which was the safety requirement -- stage 5 spawns `$49`, so
a half-registered type is a live crash rather than a missing picture.
